# Teaser motion — 文字とつなぎの動き

> 出典: open-design（nexu-io/open-design、Apache-2.0）の動きの文書（動きの帯、入りと抜け、動きの強さ、つなぎの選び方）を、ゲームのティザー向けに言い換えた（D-53）。数値は、33 本を 1 コマずつ見た記録（`research_notes/モーションデザイン/corpus_*.md`）と、736 本を明るさから自動で測った値（`research_notes/モーションデザイン/auto_measure.md`）から取った。
> 6 節だけが plan と、画・文字を変える修正に渡る（`refs::motion_text`）。それより前の節は、コード（`motion.rs`、`finish.rs`）が描くときの値と、その根拠。ジャンルごとの値は `profiles.json`。カットのつなぎの作り方と書き方は `TRANSITIONS.md`（D-70）。

## 1. 語彙

Claude は語を選ぶだけで、秒数はコードが決める。

| 種類 | 語 | 何に見えるか |
|---|---|---|
| 入り | `cut` | ぱっと出る。告げる |
| | `fade` | 静かに浮かぶ |
| | `flicker` | 明滅して点く。不穏、電気が入る |
| | `focus` | ぼけた像が寄って合う。壮大、回想 |
| | `slam` | 2.5 倍から叩きつけて止まる。衝撃の一語 |
| | `pop` | 弾んで落ち着く。軽快、やさしい |
| | `type` | 1 字ずつ打たれる（1 秒に約 20 字）。記録、通信、謎 |
| | `wipe` | 左から現れる（黒地のカードだけ。画の上ではフェード） |
| | `glitch` | 色がずれて崩れながら出る。電子的、不穏 |
| 保ち方 | `still` / `drift` / `glow` | 止まる / ゆっくり 3% 大きくなる / わずかに明るさが揺れる |
| 抜け | `cut` / `fade` / `glitch` | 消える / 静かに消える / 崩れて消える |
| つなぎ | `cut` / `dip` / `flash` / `whiteout` / `glitch` | 切る / 黒をはさむ / 白から入る / 白に飛んで戻る / 数コマ崩す |

どのつなぎもカットの尺を変えない（重ねるクロスフェードは入れない）。黒の間は台本の `black` で作る。つなぎのレシピ（何を、何秒で、どの緩急で覆い、どこで入れ替えるか）は `TRANSITIONS.md` と `transitions.json`。

各ルック（`design-systems/<id>/tokens.json` の `motion`）は、このどれかを土台にして、役割ごとに上書きする。勢い（`energy`）は秒数を伸び縮みさせる（calm 1.4 倍、measured 1 倍、driving 0.65 倍）。

## 3. 根拠

黒地の文字を 736 本で測ると、入りは約半分がカット、残りはフェードで中央値 0.5 秒（4 分位 0.33〜0.92 秒）、抜けは 6 割がカットだった。RPG のフェードが最も遅く（中央値 0.75 秒、日本語の作品は 0.79 秒）、ストラテジーは入りの 9 割近くがフェード。黒への入り方はホラーで 79% がカット、コージーとストラテジーでは 7 割前後がフェード（約 0.4〜0.6 秒）。白フラッシュが 1 秒に 3 回を超えた作品は 1 本も無く、白に飛ぶつなぎは 23% の作品（RPG 41%、日本語の作品 39%）にあった。

1 コマずつ見た 33 本では、入り方の種類がジャンルで分かれた。アクションはカット・叩きつけ（0.10〜0.17 秒）・1 字ずつ（1 秒に約 20 字）、コージーは弾む・1 字ずつ、RPG とアドベンチャーのタイトルはぼけから合う（0.9〜1.8 秒）、日本のホラーとアクションはグリッチと叩きつけが多い。

## 4. コードで守ること

- 入りは行の表示時間の 35% まで、抜けは 25% までに収め、読む時間を残す（1 字ずつは速さを上げて収める）。
- 光の強い動き（`flash`、`whiteout`、`flicker`）は、カットの中で 1 秒に 3 回を超えない（WCAG 2.3.1、NHK・民放連のガイドライン）。超えたらカット検査の P0（`flash.rate`）になる。`flicker` は 1 回で明暗 2 組。
- ルックや指示が避けた動き（`avoid`）は、入りならフェード、つなぎならカットかディップに置き換える。
- どれも編集的で、撮り直しは起きない。

## 5. ffmpeg での描き方

入りと保ち方は drawtext の不透明度と大きさの式（`t` の関数）で描く。`focus` は大きめの薄い写しが 2 枚寄ってくる形（ぼかしの近似）、`glitch` は赤と水色の写しが揺れる形、`type` は先頭から k 字の行を時間で切り替える形、`wipe` は黒い板を `overlay` で横に滑らせる形。つなぎは `TRANSITIONS.md` 5 節のレシピを `handover.rs` が描く（既定の `base` だけは、それまでの直線のフェードのまま）。

## 6. 台本に動きを書くとき

動きはルックの profile が決める。台本の行の `motion` は、強めたい行にだけ書く（1 本に 1〜3 行）。書かなければ profile のまま動く。

- 入り方の意味で選ぶ。`cut` は告げる、`fade` は静かに浮かぶ、`flicker` は不穏に点く、`focus` は壮大に像が合う、`slam` は衝撃の一語、`pop` は軽快に弾む、`type` は記録や通信のように打たれる、`wipe` は名前や章の見出し、`glitch` は電子的に崩れる。
- 1 本の中で、profile の動きに足す入り方は 1〜2 種まで。全部の行を違う動きにしない。
- `flicker` で入る行は間を空ける（つなぎの `flash`・`whiteout` と合わせて 1 秒に 3 回まで）。
- 計画の `motion` は、ブリーフや方向に「静かに」「派手に」「日本の PV のように」「フラッシュは嫌」のような言葉があるときだけ、`energy`・`variant`・`avoid` に書く。無ければ空にして、ルックに任せる。
