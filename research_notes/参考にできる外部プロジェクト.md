## rea-video（JuneYaooo/rea-video）

https://github.com/JuneYaooo/rea-video （日本語 README は `README_ja.md`。`docs/` は中国語のみ）

完成した動画をショットに分解し、どう作られたか（実写・AI 生成・3D・コード・録画）を逆算して、同じ動画を作るための計画を出すツール。shotpilot とは向きが逆で、機能の重複はない。借りるのは手法だけ。

読んだ範囲は README_ja と `docs/what-it-detects.md`、`docs/dev/aspects.md`、`docs/dev/evaluation.md`。実装本体は読んでいない。

借りられる点:

- **評価の作法**（`docs/dev/evaluation.md`）: 真値に出典を書かせる（生産記録 > プラットフォーム表示 > 目視。目視は「存疑」と明記）。規則を直したあとで初めて走らせる留出セットを必ず1組残す。AGENTS.md の「出典のある規則だけを P0、推定は P2」と同じ考え方。ショット検査の P2 を実測で校正するとき、D-20 の「Haiku でも撮れる」を数字で示すときに、留出セットを分ける運用が使える。
- **SE の吸着検査**: 各効果音を最寄りの画面イベント（字幕・カット）に ±0.2 秒で対応づけている。`script::layout` と `sound::spans` から出した位置に対して、SE がカードやカットに吸着しているかを見る検査を、サウンドチェックに足せる。映像のカットが拍に合っているか（BPM とのずれ）も同じ枠で測れる。
- **実測項目の追加**: 光比、色温、調色の傾向、字幕の出入りのタイミング。D-29 の実測はカット数や尺が中心なので、色と文字の項目は空いている。`references/craft/` に足す候補。
- **aspects の構造**（`docs/dev/aspects.md`）: 1つの観点を「逐ショット測定 → 解釈 → 全体集計 → 評価」の1モジュールにしている。shotcheck の規則を増やすときの分け方の参考になる。

取り込まない点:

- Python 実装と視覚モデル依存（「依存を増やさない」「Python は `sp_entry.py` だけ」に反する）。
- モデル能力表（`capabilities/models/*.yaml`）と routing（「エンジン抽象化は先回りしない」に反する）。
- AI 生成動画の判定とリメイク計画（対象が違う）。

## social-media-research-skills（ScrapeCreators）

https://github.com/ScrapeCreators/social-media-research-skills （MIT）

有料の ScrapeCreators API（環境変数 `SCRAPECREATORS_API_KEY`）で SNS の公開データを集め、アウトライア投稿の発見、コメント分析、競合比較、広告分析などを行うスキル13本。「出した後に、何が伸びたかを調べる」側で、shotpilot の芯（録画の前、D-02）の外にある。

読んだ範囲は README の概要と、`outlier-post-finder`、`transcript-intelligence` の SKILL.md の冒頭90行。

借りられる点は1つだけ:

- **自分の通常水準との比較**（`outlier-post-finder`）: 再生数の多さではなく、そのアカウント自身の中央値に対する倍率（`view_lift = post_views / median_views`）で「当たり」を決める。D-29 のジャンル別パッケージに入れるティザーを選ぶとき、再生数の大きいゲームほど有利になる偏りを避けられる。ただし、集めた 701 本に再生数と投稿元チャンネルの情報があるかは未確認。無ければ使えない。

取り込まない点:

- 有料 API と、スクリプトの Python/Node 前提（依存を増やさない方針に反する）。
- `transcript-intelligence` のフック → 前提 → 主張 → 根拠 → 見返り → CTA の分割は、骨格の `hook → establish → escalate → title` とほぼ同じで、新しい知見はない。
- コメント分析、競合分析、広告分析は、撮影レーンの外。
